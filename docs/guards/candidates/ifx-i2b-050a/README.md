## What changes in an adapter

1. **Pin split.** A dropped binding keeps the safe read of the file: path under TargetRoot, no links, file
   present. It no longer compares the file with a Profile hash. The module's checks already run on the content
   (`checkBasis` in the specification): regex predicates, recomputed snapshots and projections, reconciliations,
   and surface counts. A kept binding is enforced as before: `integrity-failure` on any difference.
2. **Tree fingerprints.** Live trees (`src`, `src/Modules`, `src` + `tests`, the Plan04 fixtures, the presentation
   and transaction-handler sources) are no longer compared with the Profile. The G05 diagram tree stays pinned
   (governance).
3. **Lock binding.**
   - The lock is `EvidenceRoot/locks/<gate>/evidence-lock.json`, with its evidence files beside it. The type gate
     also stages `assembly-manifest.json` and the DLLs.
   - The module verifies the producer id and the producer script SHA-256 pinned in its policy, `targetCommit` equal
     to HEAD, the unchanged freshness window, the source fingerprint, every listed file hash and the lineage
     between locks.
   - Missing evidence is `prerequisite-missing`; anything else inconsistent is `integrity-failure`.
   - `ifx-database-evidence` compares its three live authorities with the hashes the lock recorded at the same
     commit.
4. **Couplings.**
   - The G03 projection is regenerated by `ifx-g03-governance-core` from the current catalog and must equal the
     committed file (R2). The two G05 modules read the checked file.
   - `ifx-c1-evaluated-reference` and `ifx-plan04-abstractions` embed the three `docs/guards/candidates` policies
     they read.
   - `ifx-c1-type-provenance` embeds the two V3_ifx rule and policy files.
   - The Profile drops `docs/guards/V3_ifx/stages/post/gates/specialized` from `workspaceEvidence`.
   - The generated producer's V3 scanner source and the frontend producer's fixed Windows `PATH` go with the
     producer relocation (0.5.0-b).

## Proving the change (A1-3 suite rule)

Every changed module adds three suite cases:

- **(a)** a benign edit of each formerly pinned live file still passes;
- **(b)** a rule-breaking edit of a live input still blocks with the module's rule;
- **(c)** an edited governance file is still `integrity-failure`.

A check that stops blocking under (b) depended on the hash alone and is rewritten before the harness work (A1-4).

Lock consumers also reject:

- a missing lock;
- an expired lock;
- a lock for another commit;
- a forged producer hash;
- a tampered evidence file.

## Known consequences

- A change to a kept governance file (for example a G05 phase evidence document or a G04 runbook) still needs a
  bundle update. That is the intent of the rule.
- The committed G03 projection is still regenerated by the V3 export script when the catalog changes. V4 checks
  it, but does not produce it. A V4-owned regeneration command belongs to 0.5.0-b or I3.
- Moving the producers in 0.5.0-b changes the pinned producer hashes, so 0.5.0-b issues 0.5.1.
