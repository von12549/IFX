# Coding Guardrails 门禁架构讨论草案

> 状态：讨论中。“已确认”记录已经达成的取舍；“提案”仍待确认。本文不是执行 plan。
>
> 范围：只借鉴 `AI_CODING_GUARDRAILS.md` 的门禁分层思路，不采纳其中具体技术选型、代码规范或对 AI agent 的命令式要求。

## 已确认的目标

1. 建立覆盖编码前、编码中、编码后、最终变更集及 CI 的完整门禁架构。
2. 既能映射 IFX 现有的 LayerGuard 和治理检查，也能通过替换项目适配配置用于新项目。
3. 本阶段讨论并沉淀原则；具体工具改造、脚本、CI 编排和分阶段实施留给后续执行 plan。
4. 后续 plan 的交付物应包含一套带 `README.md` 的完整门禁文档目录。Tech Stack、Rule 等输入可手动修改；AI Agent 应能从 README 进入，按受控流程重新生成和验证适用的门禁。

## 已确认的执行取舍

1. 普通变更使用简短的 Pre-Code 影响面摘要；跨模块、公共契约、数据库、认证/租户、消息或部署等高风险变更保存独立、可审查的决策记录。不要求每次普通代码变更都新增一个文件。
2. Agent 工作流必须执行适用的本地检查；本地 hook 主要提供快速反馈。是否允许合入由 CI 的 required checks 决定，不能把本地 hook 当作最终权威。
3. 定义统一的规则与结果契约，保留 IFX 已有专用 validator 及可并行的 CI 工作流；不以单一巨型脚本替代全部检查。统一入口命令可作为编排接口，不改变规则来源和专用检测器的职责。
4. 首版再生成只负责文档索引、规则覆盖矩阵和新门禁框架。`src/layerguard.json` 及 G03/G04/G05 的现有权威链保持现状；再生成流程读取、校验并引用它们，不将这些策略迁移成由 `docs/guards` 生成。

## IFX 当前事实与缺口

| 能力 | 已有承载 | 架构上的位置 |
| --- | --- | --- |
| 静态项目/层/ownership/契约边界 | `src/layerguard.json`、LayerGuard MCP/CLI | 编码中可查询；编码后和 CI 可强制验证 |
| 契约、运行时、上下文语义 | G03/G04/G05 validators、协议与行为测试 | 补足 LayerGuard 无法证明的语义与运行时行为 |
| 数据库与迁移边界 | Database Boundary tests、迁移安全脚本及 CI | 高风险变更专门门禁 |
| 构建与测试 | `IFX.sln`、相关测试项目、G04/G05 verification 脚本 | 编码后与 CI 验证 |
| 编码前项目指导 | `CLAUDE.md`、Copilot 指令、架构文档 | 有指导材料，尚无跨 agent 的统一任务级 Pre-Code Guard |
| 最终变更集复核 | 常规 git diff/PR review | 尚无统一的 Diff Guard 规则、输出契约和 CI 映射 |

现有 CI 由多个工作流分别执行 LayerGuard、G03、G04、G05、Plan 04 和数据库检查。LayerGuard 的 MCP `check` 返回即时扫描结论；`scripts/Invoke-LayerGuard.ps1` 通过 CLI 加上当前 `plan05.json` 空 baseline 对账。已有检查应被复用，不应仅为形成“完整架构”而复制相同规则。

## 提案：门禁分层

```text
项目约束与规则目录（唯一权威、可追溯）
        ↓
Pre-Code Guard：归属、影响面、现有模式、风险与验证路径
        ↓
实现过程中的快速反馈：局部静态检查、受影响项目构建/测试
        ↓
Post-Code Guard：完整静态检查、编译、定向/集成/行为测试
        ↓
Diff Guard：以最终 diff 独立复核范围、契约、依赖、迁移及门禁本身的变化
        ↓
CI Hard Gate：在干净环境重跑必需检查、核对证据并决定合入资格
```

Architecture Tests 不是只在最后运行的一道独立关卡，而是 Post-Code 与 CI 使用的一类检测器：项目图和命名约束交给 LayerGuard；需要编译器符号、装配关系或运行时语义的规则交给分析器、架构测试及行为测试。每条规则必须说明检测器能证明什么、不能证明什么，避免多个“绿色”结果掩盖同一盲区。

## 提案：跨项目通用原则

1. **规则先于工具。** 每条需要执行的规则应有稳定 ID、适用范围、权威来源、检查方式、失败等级、证据和例外流程。文档负责解释意图；可机器判定的部分进入硬门禁。一个事实只有一个权威来源，多个执行点复用它。
2. **Pre-Code 识别变化，不能伪称已经验证代码。** 至少确定 owning module、受影响层/项目、类似实现、新依赖、跨模块交互、公共契约/数据库/安全影响，以及对应的后续检查。高风险或跨边界变更应先形成可审查的决策记录。
3. **快速反馈与最终证明分开。** 本地按影响面先运行便宜、定向的检查；CI 在干净环境运行规定的完整范围。局部通过不等于全仓通过，跳过、未运行和失败必须分别表达。
4. **Diff Guard 独立审查最终结果。** 它既检查误改、遗漏测试、无关清理和生成物，也识别新增依赖、公共契约、数据库迁移、认证/租户边界，以及规则、baseline、validator、CI 本身的改动。机械可判定项由工具拦截；意图和业务语义由审查者判断。
5. **不同检测器互补。** 静态结构、编译器语义、行为测试、部署/数据证据各自给出有限结论；不能用 LayerGuard 的绿色结果替代 G03/G04/G05 或数据库测试。
6. **CI 是合入的最终机械门禁。** 必需检查不允许因输入缺失、扫描不完整、报告缺失、过期例外或策略哈希漂移而绿色通过。哪些 CI 状态是仓库保护规则中的 required checks，需要在实施时明确核验。
7. **例外必须显式且有期限。** 例外记录 owner、理由、风险、创建与到期时间、删除条件；不可豁免类别明确列出。修改规则、baseline 或检测器本身不能被普通代码变更悄悄绕过。
8. **通用骨架与项目适配分离。** 通用部分定义阶段、规则元数据、触发条件、结果/证据格式和失败语义；项目配置提供模块图、关键路径、语言工具链与专用 validators。IFX 绑定 LayerGuard/G03/G04/G05/数据库；新项目可替换绑定而保留流程。

## 提案：可编辑文档目录与门禁再生成

后续 plan 可交付如下项目无关的目录骨架，并在 IFX 中填写项目绑定；这只是信息架构，具体文件格式、命令名和迁移步骤由执行 plan 设计。

```text
docs/guards/
  README.md                 # 人与 Agent 的唯一入口：文件角色、修改/再生成/验收流程
  principles/               # 已确认的不变量与决策
  inputs/
    TECH_STACK.md           # 可编辑：语言、框架、构建/测试工具链及其版本策略
    PROJECT_MAP.md          # 可编辑：模块、层、owner、关键路径与风险触发器
    rules/                   # 可编辑：稳定 ID、适用范围、等级、权威来源、检测目标
  bindings/                 # 项目适配：IFX 指向 LayerGuard、G03/G04/G05、数据库等
  contracts/                # 输入 schema、检查结果与证据契约
  generated/                # 派生的覆盖矩阵、输入摘要、产物清单；不手改
```

README 应给出一条可重复的 Agent 工作流：读取原则和全部权威输入 → 验证结构和规则 ID → 计算受影响的检测器与输出 → 再生成 → 运行检测器自身的正/反例测试与适用检查 → 比较最终 diff → 报告覆盖范围、未实现规则及失败。再生成必须可重复、尽量幂等，并提供只检查漂移而不改文件的 CI 模式。AI 可以负责解释和编排，但不能以一段自然语言解释代替机器校验，更不能把“未生成”报告为“通过”。

可编辑 Markdown 适合解释意图；需要生成硬门禁的字段必须有可验证的结构（例如 schema 约束的 front matter 或独立结构化数据），包括规则 ID、适用范围、权威来源、执行器、强制级别和例外策略。每条规则必须追溯到生成物或既有检测器；尚无检测器时明确标为未覆盖，不能让报告显示绿色。

IFX 现有 `src/layerguard.json` 与 G03/G04/G05 的权威链已承担策略职责。首版再生成器通过 `bindings/` 读取、校验和引用它们，不复制相同事实到 `inputs/rules/`。手改规则后，系统要么完成首版范围内受影响产物的生成和验收，要么明确报告“需要修改现有权威输入”或“该规则尚无检测器”；不能悄悄覆盖人工维护的代码或降低现有规则。未来若要让文档规则直接生成 `src/layerguard.json`，应另立权威来源迁移，证明生成结果与现行策略等价，并同步 hash、baseline、测试和 CI；本次执行 plan 不包含该迁移。
