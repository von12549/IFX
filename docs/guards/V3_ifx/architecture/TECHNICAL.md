# Technical design

The generic V3 runner is source-only until `Generate` runs. In this IFX fork, `profiles/ifx/` has been configured and both .NET outputs are checked in under `generated/`. `scripts/Invoke-V3.ps1` is a PowerShell 7 bootstrapper; it validates a profile, project map, tech stack and rule JSON against local schemas, rejects duplicate IDs, unresolved command references and unsafe path patterns, then copies versioned C# templates plus an input snapshot into a generated xUnit project. `Check` renders the same expected files in memory and compares UTF-8 bytes, including the file set outside `bin/` and `obj/`. It never edits another guard project.

The second generator, `scripts/Invoke-IFX.ps1`, copies the package-owned LayerGuard .NET solution from `templates/ifx-layerguard/` into `generated/dotnet/LayerGuard/` and byte-checks its entire source/fixture set. Its strict scan reads `policy/layerguard.json` and package-local G03/G04/G05 binding files. See [IFX migration record](IFX-MIGRATION.md) for the ownership boundary and verification.

The generic `Invoke-V3Setup.ps1 -Mode Analyze` now seeds target-specific Markdown drafts under `analysis/ifx/` while preserving edits. `Invoke-V3Architecture.ps1 -Mode Review` parses JSON blocks, checks inventory hashes, validates a proposed profile, compares it with `profiles/ifx/` and observes direct project-reference violations; prose requires human or Agent interpretation. `-Mode Adopt -AcceptDocument` can write a new profile path after review, without rewriting the current IFX profile or independent policy. `Invoke-IFX.ps1` validates numbered rule-ID and local authority alignment before its existing generate/check/test/scan work.

The generated stage project has three test categories. `Self` exercises the project and optional compiled detectors. `Post` checks declared project references plus the explicit CRM Domain/Contracts Debug assemblies. It fails on missing DLLs, identity drift or empty type groups and writes `artifacts/guards/v3-assembly.json`. `Diff` compares final Git paths, including both sides of renames and local untracked files, with a formal Plan's exact `plannedPaths`. The `Test` command runs `Self` and `Post`; `Diff` runs the scope test separately. Both receive the target root through process environment variables set by the bootstrapper. CI should supply explicit base/head revisions to Diff, then require the job status.

Pre maps exact proposed paths to the most specific IFX area, owner, nearby implementation, applicable rule IDs and focused command IDs. An ordinary summary blocks unknown or risk-triggered paths. A formal Plan additionally requires matching Markdown and JSON filenames, all affected area/rule/command IDs and a covering decision record for every risk path. It does not evaluate decision quality or approval. Both modes emit a schema-checked advisory/blocked JSON result and SHA-256 of the selected profile inputs. The Agent Skill and Hook only call this validator; they are not hard merge gates.

The project-reference detector is intentionally narrow: it reads `ProjectReference Include` elements from matching `.csproj` files. It does not resolve MSBuild conditions, transitive graph edges, Roslyn symbols or runtime behavior. The profile's `coverage` is therefore `partial`. The ArchUnitNET pilot adds actual compiled type-dependency evidence but still has partial coverage; new kinds need a schema, implementation and positive/negative fixtures before `blocking` is permitted. A project with non-.NET source can still use the Plan/Pre layer, but needs a new detector adapter for code checks.

Generated xUnit dependencies are pinned in the project template. For an isolated or offline test, pass `-NuGetConfig` pointing to a project-local NuGet config; the caller can set `NUGET_PACKAGES` to an existing readable cache. The generated project is reproducible from the profile and templates, not created through an AI prompt or `dotnet new` state.
