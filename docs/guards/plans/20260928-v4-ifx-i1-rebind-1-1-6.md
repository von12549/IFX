## 2. What changes from 1.1.5 to 1.1.6 for IFX

`core/distribution/**` (installer, `Compose-V4Extension.ps1`, verifier) and the CLI contract are
unchanged. Host and Web Companion IL are identical. The archive loses the two Companion
`staticwebassets` manifests and gains `trust-policy.json`, `trust-change-authorization.schema.json` and

differs from the base, and a production review binds `baseArchiveSha256`.

**Expected 0.4.4 difference from 0.4.3.** In the default case (D1-A below) it is the same four
Profile/manifest files as in T7: `bundle-manifest.json`, `profile.json` (version and seven fresh lock
references), `authority-map.json` and `evidence-lineage.json`. All 36 external modules are exact
inheritance. D1-B adds exactly one module change (`ifx-database-evidence/module.json`, its timeout).

## 3. The two backlog items

**IFX-V4-003 (installer path).** `ifx-gate-coverage-c6c1/Test-IFXC6DualPlatformCandidate.ps1` line 88 runs
`<TargetRoot>/docs/guards/v4/core/distribution/Install-V4Distribution.ps1`; since T8 that path is gone.

Fix: a successor Linux positive runner in `docs/guards/candidates/ifx-rebind-116/`.

- It extracts `v4-guards-1.1.6/package/core/distribution/Install-V4Distribution.ps1` from the
  hash-verified base archive into `WorkRoot`, and then installs from that archive.
- It still asserts that the Linux receipt payload equals the Windows receipt.
- A negative control proves it never reads `docs/guards/v4`.
- The accepted c6c1 script stays unchanged.

**IFX-V4-002 (Linux timeout).** In the T7 diagnostic, the C6c Linux leg put `TargetRoot` and `WorkRoot`
under `/out`, a bind mount of a Windows directory. The adapter needed 73–85 s against its 60 s timeout,
and the workload and module bytes are identical to 0.4.2.

Two changes:

- **Harness.** Successors of `Invoke-IFXC6ParallelCertification.ps1` and
  `Invoke-IFXC6LinuxCertification.ps1` place the Linux `TargetRoot` and `WorkRoot` on container-native
  storage and copy only the reports to `/out`. `/source` stays a read-only bind mount; it is read once by
  the copy.
- **Measure first (S3), then decide:**
  - **D1-A:** the module's worst case on native Linux storage is at most 45 s (25 % margin) in 3/3 runs.
    The module is unchanged, and the harness fix closes IFX-V4-002.
  - **D1-B:** otherwise, stop and ask the operator. The proposal would be to raise
    `ifx-database-evidence` `timeoutSeconds` from 60 to 180, the value other IFX modules already use, in a
    successor module candidate. The contract handshake then expects 35 exact inheritances plus 1 focused
    requalification. The C6d packet shows that module diff. V4 has no platform-scaled timeout, and adding
    one would be a Guard product change, which is out of scope.

Linux in C6c stays a **non-blocking** assessment under C6c22. The acceptance target is a visible Linux
`pass`, but making Linux blocking is a P10.GATE decision (I2).
