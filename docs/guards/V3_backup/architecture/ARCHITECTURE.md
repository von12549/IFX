# Architecture and coverage contract

V3 has two responsibilities. Before coding, a Plan skill, template and optional hook help an Agent state intent, paths, risks, owners and evidence. `Pre` uses a project map and rule applicability patterns to check an ordinary path summary or formal Plan against known areas, rules, commands and decisions. After coding, a generated .NET project performs independent structural checks. `Check` proves the project matches the configured source; `Test` runs detector self-tests and the target scan. Its `Diff` test compares final Git paths against a formal Plan; risk metadata is checked by Pre and must also be reviewed in CI.

The default package is project-neutral. `Init` creates an unreviewed configuration that fails to map real source paths; `Analyze` supplies evidence and editable target-specific `ARCHITECTURE.md`/`TECHNICAL.md` drafts but never activates policy. `Review` parses their structured JSON blocks, validates a proposed profile, compares it to current profile inputs and observed direct project references, and reports unmapped paths or detector gaps. Prose needs human or Agent interpretation into those blocks. After both documents are marked reviewed, explicit `Adopt` can write a new profile without overwriting current policy. Detector implementations are versioned templates, not prose synthesis. Each rule has a unique ID, kind, enforcement, authority and coverage. `blocking` is accepted only for implemented detector kinds with positive and negative self-tests. An unsupported detector kind fails generation; a rule with no detector must remain advisory/uncovered.

JSON is the sole machine authority. Markdown views are deterministic summaries and structured JSON companions; free-form notes live outside generated views. `Check` detects drift and `Import` accepts an edited JSON block only against its recorded source hash, followed by schema and profile validation. The generated coverage matrix states only V3 stage detector coverage and cannot imply that an external architecture gate is active.

Supported project detector: `forbidden-project-reference`. It scans matching `.csproj` files and rejects `ProjectReference Include` values matching a forbidden target glob. This checks declared project edges only. It does not analyze transitive references, imports, compiled assembly references, symbol binding or behavior. Keep an existing specialized detector for those requirements.

The [optional ArchUnitNET detector](ARCHUNITNET.md) adds Post evidence from compiled assemblies: actual type dependencies, interface implementations and declaration location. It is a separate evidence source inside the generated .NET project, not a replacement for declared project edges, Pre/Diff or behavior tests. Its package reference and test file are conditional on a configured assembly rule. A future target rule that forbids Application dependencies on public Contracts must be enabled only after the target architecture and every affected module have been reviewed and migrated.

The generated .NET project is placed under V3 by default, but GitHub Actions workflows and Agent host registration must be installed at host-specific paths outside V3 to be active. Generation and activation must remain separate operations. No generated output may rewrite an existing authority or gate.
