# Technical design

The package is source-only until `Generate` runs. `commands/Invoke-V3.ps1` is the PowerShell 7 bootstrapper; it validates a profile, project map, tech stack and rule JSON against local schemas, rejects duplicate IDs, unresolved command references and unsafe path patterns, then copies versioned C# templates plus an input snapshot into a generated xUnit project. `Check` renders the same expected files in memory and compares UTF-8 bytes, including the file set outside `bin/` and `obj/`. It never edits an existing policy authority or another guard project.

`Invoke-V3Setup.ps1` has two pre-configuration modes. Init creates schema-valid placeholder inputs without a blocking rule and refuses overwrite. Analyze walks repository files while excluding transient directories and explicit globs, parses literal `.csproj` XML and package scripts, and records paths plus SHA-256 hashes. It does not run MSBuild, resolve conditional/transitive references, infer ownership, or change policy. `Invoke-V3Docs.ps1` renders LF/UTF-8 Markdown views from the selected JSON profile, checks exact content and file set, and can import edited fenced JSON after base-hash, schema and full-profile checks. If profile validation fails, import restores the prior bytes. Hand-written rationale is kept outside `views/`.

Analyze also calls `Invoke-V3Architecture.ps1 -Mode Draft` once per missing target document, preserving edits on later scans. `Review` requires fresh inventory hashes, extracts schema-checked profile/map/rule/tech JSON blocks, validates a generated `review-profile/` proposal, and compares it with existing inputs and literal direct `ProjectReference` edges. It reports scope gaps and violations without changing the selected profile. `Adopt` requires both documents marked `REVIEWED` and an explicit `-AcceptDocument`; it writes a new profile path only. The caller still runs generated-project tests and independently activates CI. The package-level architecture documents remain design references, while analysis drafts are target-specific proposed inputs.

The generated test project has three test categories. `Self` contains compliant and violating fixtures for the project detector and, when selected, both compiled-rule kinds. `Post` scans `.csproj` files and checks explicit compiled assemblies. A project rule must match at least one source; an assembly rule must load its declared assemblies and match at least its configured minimum types or implementations. `Diff` compares final Git paths, including both sides of renames and local untracked files, with a formal Plan's exact `plannedPaths`. The `Test` command runs `Self` and `Post`; `Diff` runs the scope test separately. Both receive the target root through process environment variables set by the bootstrapper. CI should supply explicit base/head revisions to Diff, then require the job status.

Pre summary mode maps exact proposed paths to areas, owners, nearby implementations, applicable rule IDs and focused command IDs. It blocks unknown paths and risk-triggered paths. Formal mode additionally requires matching Markdown and JSON filenames, all affected areas, all applicable rules, focused command IDs and covering decision records for risk paths. It does not evaluate a decision's quality or approval. Both modes write a schema-checked result with a SHA-256 of selected profile inputs under `artifacts/guards/` by default; a successful Pre result is advisory. The Agent Skill and Hook only call this validator; they are not hard merge gates.

The project detector is intentionally narrow: it reads `ProjectReference Include` elements from matching `.csproj` files. It does not resolve MSBuild conditions, transitive graph edges, Roslyn symbols or runtime behavior. The profile's `coverage` is therefore `partial`. Future detector kinds must add an implementation, schema variant and both positive and negative fixture tests before `blocking` is permitted. A project with non-.NET source can still use the Plan/Pre layer, but needs a new detector adapter for code checks.

The [ArchUnitNET detector](ARCHUNITNET.md) uses a conditional template and pinned `TngTech.ArchUnitNET` 0.13.4 reference. `tech-stack.json:assemblyGate` lists the build target and each expected assembly source `.csproj`, exact Debug DLL path and identity. `Test` builds the target and each listed project with `--no-incremental` before testing. Its report records rule IDs, expected/loaded assemblies, matched counts, violations and a tech-stack hash. Missing binaries, identities, interfaces or zero matches fail. Project declarations remain checked by the existing detector.

Generated xUnit dependencies are pinned in the project template. For an isolated or offline test, pass `-NuGetConfig` pointing to a project-local NuGet config; the caller can set `NUGET_PACKAGES` to an existing readable cache. The generated project is reproducible from the profile and templates, not created through an AI prompt or `dotnet new` state.
