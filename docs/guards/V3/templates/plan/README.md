# Formal Plan pair

Use one Markdown plan and one JSON sidecar with the same `YYYYMMDD-short-slug` stem for substantial or high-risk work. Small ordinary changes may keep a brief impact summary in task notes. The JSON is machine input; the Markdown explains intent, architecture tradeoffs, steps and evidence. The Agent must update both if scope changes. The Pre validator checks structure and risk coverage, not business correctness or approval.

The files in this directory are examples; copy and rename them before use.
